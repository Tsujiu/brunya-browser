1. Alternativas

Há dois caminhos jurídicos diferentes.

Alternativa A — licença não exclusiva. O colaborador continua titular
da contribuição e concede ao projeto uma licença expressa para usá-la.
É a alternativa que este repositório adota agora, porque um Pull Request
consegue registrar essa autorização com menos risco de forma inválida.

Alternativa B — cessão dos direitos patrimoniais ao titular. O
colaborador transfere a titularidade econômica da contribuição. A Lei
nº 9.610/1998, artigo 49, trata a cessão como ato escrito e de
interpretação restritiva. Direitos morais não se transferem. Um
checkbox no GitHub é uma base fraca para essa cessão. Se o titular
quiser a alternativa B, o caminho é um instrumento próprio, assinado,
redigido por advogado. Este arquivo não opera a alternativa B.

3. O que o colaborador concede

Ao registrar o aceite abaixo, o colaborador concede ao titular uma
licença não exclusiva, mundial, gratuita, pelo prazo de proteção legal,
para:

a) reproduzir, modificar, integrar e manter a contribuição;

b) distribuir a contribuição como parte do Brunya Browser, em código ou
   em binário, sob as condições que o titular definir para o projeto;

c) autorizar terceiros a usar a contribuição somente na medida
   necessária para esse uso do projeto, inclusive por uma licença
   futura escolhida pelo titular.

A licença não é exclusiva. Não é cessão. Não impede o colaborador de
licenciar a mesma contribuição a outras pessoas.

O colaborador autoriza as modificações necessárias para integrar a
contribuição ao projeto. Isso não é renúncia a direito moral que a lei
torne irrenunciável.

4. Contribuição rejeitada

Se o Pull Request não for integrado, o titular não passa a ser dono do
código. A licença da seção 3 continua valendo para a cópia enviada, de
modo que guardar e examinar o diff não dependa de um novo pedido. O
titular não publica uma contribuição rejeitada como parte do produto,
salvo autorização específica.

5. Declarações do colaborador

O colaborador declara que:

a) escreveu a contribuição ou tem autorização de quem a titula para

b) a contribuição não inclui código, ícone, texto ou dado de terceiro

c) não envia segredo, dado pessoal desnecessário ou material confidencial

6. Como o aceite fica registrado

O aceite não ocorre porque CLA.md está no repositório. O colaborador
registra o aceite escrevendo, no corpo do Pull Request, esta frase
exata:

Aceite do CLA: eu li CLA.md (CLA-BRUNYA-2026-11-02) e concedo ao titular a licença não exclusiva descrita nesse documento.

O fluxo `.github/workflows/cla.yml` recusa a integração automática
quando a frase não está no corpo do Pull Request. O Pull Request, com
autor, data e texto, é o registro. Não é assinatura eletrônica
qualificada.

Contribuição relevante, ou qualquer pedido de cessão, pode exigir um
instrumento assinado fora do GitHub. O titular pode recusar a
contribuição enquanto esse instrumento não existir.
